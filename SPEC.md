# Спецификация приложения «Календарь звонков»

> **Статус архитектурных решений:** стек **React + Express API + SQLite**
> является предварительным и будет уточняться в ходе обсуждения.
> Функциональные требования ниже от выбора стека не зависят.

## 1. Обзор

«Календарь звонков» — упрощённый сервис бронирования времени на созвоны по мотивам
[Cal.com](https://cal.com/). Владелец календаря публикует доступное время для встреч,
а любой посетитель выбирает свободный 30-минутный слот и записывается на звонок.

Это небольшое, но законченное приложение: без авторизации, личных кабинетов и
интеграций с внешними календарями.

### 1.1. Роли

- **Владелец календаря** — настраивает расписание доступного времени и смотрит
  список предстоящих встреч.
- **Посетитель** — без регистрации просматривает свободные слоты и записывается
  на звонок.

## 2. Цели и не-цели

### 2.1. Цели

- Посетитель видит свободные 30-минутные слоты на ближайшие дни.
- Посетитель может выбрать слот, указать свои данные и оформить запись.
- Владелец видит список предстоящих встреч.
- Владелец может настроить расписание доступного времени.

### 2.2. Не-цели

- Регистрация, логин, личные кабинеты, права доступа.
- Интеграции с Google Calendar, Outlook и т.п.
- Календарь посетителя, повторяющиеся события.
- Оплата, напоминания по email/SMS, отмена записи посетителем.
- Многопользовательность (календарь один, владелец один).

## 3. Сценарии использования

### 3.1. Посетитель записывается на звонок

1. Посетитель открывает публичную страницу бронирования.
2. Видит ближайшие доступные даты и свободные 30-минутные слоты.
3. Выбирает слот и заполняет форму записи (имя, email, при необходимости комментарий).
4. Получает подтверждение записи с деталями встречи.

### 3.2. Владелец настраивает расписание

1. Владелец открывает страницу настроек.
2. Для каждого дня недели указывает рабочие часы (или отмечает день выходным).
3. Сохраняет расписание — доступные слоты пересчитываются.

### 3.3. Владелец смотрит предстоящие встречи

1. Владелец открывает страницу встреч.
2. Видит список предстоящих записей: дата, время, имя и контакт посетителя.
3. Может отменить запись; освободившийся слот снова становится доступным.

## 4. Функциональные требования

### 4.1. Публичная страница бронирования

- Отображает свободные слоты только на **ближайшие 7 дней** (включая текущий день).
- Слоты, время которых уже наступило (прошлые слоты сегодня), не показываются.
- Список слотов сгруппирован по датам.
- Занятые слоты исключаются из списка.
- Свободные слоты показываются с указанием времени начала и конца (по 30 минут).

### 4.2. Создание записи

- Форма записи содержит поля:
  - **Имя** (обязательное),
  - **Email** (обязательное, валидация формата),
  - **Комментарий** (необязательное, до 500 символов).
- Одновременно бронируется ровно один слот.
- При попытке записаться на уже занятый слот возвращается ошибка
  «Слот занят» — повторная запись на один слот невозможна.
- После успешной записи посетитель видит страницу подтверждения с деталями
  встречи (дата, время, данные владельца).
- Один слот — одна запись. Гостевые записи не различаются по пользователям
  (двойная запись на один слот с одного email блокируется на уровне слота).

### 4.3. Настройки расписания (владелец)

- Расписание задаётся для **дней недели (Пн–Вс)**.
- Для каждого дня можно указать:
  - интервал начала и конца рабочего дня (шаг 30 минут),
  - признак «выходной» (слотов нет).
- Доступные слоты генерируются из расписания начиная с текущего дня.
- Изменения расписания вступают в силу сразу. Существующие записи не удаляются,
  но занятые слоты остаются занятыми даже если день позже был помечен выходным.

### 4.4. Список встреч (владелец)

- Показывает все предстоящие записи, отсортированные по дате и времени.
- Каждая запись содержит: дату, время начала, имя, email, комментарий посетителя.
- Владелец может **отменить** запись — слот снова становится свободным.
- Встречи с неактуальными слотами исключать из списка не требуется, достаточно
  показывать записи от текущего момента и позже.

### 4.5. Данные владельца для посетителя

- На публичной странице выводятся имя владельца (например, «Созвон с <имя>»)
  и его email. Эти данные настраиваются владельцем в настройках.

## 5. Бизнес-правила

- **Продолжительность слота**: 30 минут.
- **Горизонт бронирования**: 7 дней вперёд от текущего дня.
- **Генерация слотов**: на каждый день недели слоты строятся последовательно от
  начала к концу рабочего интервала (например, 10:00–10:30, 10:30–11:00, …),
  слот не пересекает границу интервала и не начинается в нерабочее время.
- Слот, попавший в прошлое, не показывается и не бронируется.
- Слот с активной записью считается занятым и недоступным.
- Все времена — в **таймзоне сервера** (упрощение, выбора часового пояса нет).
- Данные посетителя обязательны для записи; запись без имени или некорректного
  email отклоняется с сообщением об ошибке.

## 6. Модель данных (SQLite)

### 6.1. Таблица `owner_settings`

Параметры владельца (одна строка).

| Поле            | Тип    | Описание                              |
|-----------------|--------|---------------------------------------|
| `id`            | INTEGER| PK, всегда `1`                        |
| `name`          | TEXT   | Имя владельца, отображается посетителям |
| `email`         | TEXT   | Email владельца                       |

### 6.2. Таблица `weekly_schedule`

Расписание по дням недели.

| Поле        | Тип    | Описание                                     |
|-------------|--------|----------------------------------------------|
| `id`        | INTEGER| PK                                           |
| `weekday`   | INTEGER| День недели 0–6 (Пн–Вс)                     |
| `start_time`| TEXT   | Начало рабочего дня, `HH:MM`                 |
| `end_time`  | TEXT   | Конец рабочего дня, `HH:MM`                  |
| `is_day_off`| INTEGER| `0/1` — выходной день, слотов нет            |

Ограничение: для одного дня недели не более одной строки.

### 6.3. Таблица `appointments`

Записи на звонки.

| Поле        | Тип     | Описание                        |
|-------------|---------|---------------------------------|
| `id`        | INTEGER | PK                              |
| `date`      | TEXT    | Дата слота, `YYYY-MM-DD`        |
| `start_time`| TEXT    | Начало слота, `HH:MM`           |
| `guest_name`| TEXT    | Имя посетителя                  |
| `guest_email`| TEXT   | Email посетителя                |
| `comment`   | TEXT    | Комментарий (может быть пустым) |
| `created_at`| TEXT    | Время создания записи           |

Ограничение: уникальность пары `(date, start_time)` — один слот занимается один раз.

## 7. API (REST, Express)

Базовый путь `/api`.

### 7.1. Публичные эндпоинты

| Метод | Путь            | Описание                                         |
|-------|-----------------|--------------------------------------------------|
| GET   | `/api/settings` | Имя и email владельца (для публичной страницы)   |
| GET   | `/api/slots`    | Свободные слоты на ближайшие 7 дней              |
| POST  | `/api/appointments` | Создать запись `{ date, startTime, guestName, guestEmail, comment }` |

Ответ `GET /api/slots` — `{ "days": [ { "date", "slots": [ { "start", "end" } ] } ] }`.
Пустые даты (все слоты заняты) включаются с пустым массивом `slots`.

`POST /api/appointments`:
- при успехе — `201` и созданная запись;
- при невалидных данных — `400` с описанием ошибок полей;
- при занятом или прошедшем слоте — `409` с сообщением «Слот занят».

### 7.2. Эндпоинты владельца

| Метод  | Путь                   | Описание                                   |
|--------|------------------------|--------------------------------------------|
| GET    | `/api/schedule`        | Текущее недельное расписание               |
| PUT    | `/api/schedule`        | Сохранить расписание на неделю             |
| GET    | `/api/appointments`    | Предстоящие записи                         |
| DELETE | `/api/appointments/:id`| Отменить запись (освободить слот)          |

`PUT /api/schedule` принимает массив из 7 элементов
`[ { start, end, isDayOff } ]` (Пн–Вс) и заменяет расписание целиком.
Валидация: `start < end`, значения в формате `HH:MM` и кратны 30 минутам.

## 8. Интерфейс (React)

### 8.1. Страницы

| Маршрут                  | Назначение                                     |
|--------------------------|------------------------------------------------|
| `/`                      | Публичная страница бронирования                |
| `/booking/:date/:time`   | Форма записи на выбранный слот                 |
| `/success/:id`           | Подтверждение записи                           |
| `/owner/schedule`        | Настройки расписания (владелец)                |
| `/owner/appointments`    | Список предстоящих встреч (владелец)           |

### 8.2. Публичная страница (`/`)

- Заголовок «Созвон с <имя владельца>».
- Список ближайших 7 дней, в каждом — свободные слоты.
- Клик по слоту ведёт на `/booking/:date/:time`.

### 8.3. Форма записи (`/booking/:date/:time`)

- Показывает выбранную дату и время.
- Поля: имя, email, комментарий.
- Кнопка «Записаться».
- Ошибка «Слот занят» отображается, если слот занят к моменту отправки.

### 8.4. Подтверждение (`/success/:id`)

- Детали встречи: дата, время, имя и email владельца.
- Подтверждение «Запись создана».

### 8.5. Настройки расписания (`/owner/schedule`)

- Для каждого дня недели: время начала, время конца, чекбокс «Выходной».
- Кнопка «Сохранить».
- Форма сообщает об успехе сохранения или ошибках валидации.

### 8.6. Встречи (`/owner/appointments`)

- Таблица предстоящих встреч: дата, время, имя, email, комментарий.
- Кнопка «Отменить» у каждой записи с подтверждением в интерфейсе.

## 9. Нефункциональные требования

> Ниже — предварительные решения по стеку, подлежат уточнению.

- **Стек**: React (клиент), Express (API), SQLite (`better-sqlite3`).
- **Сборка клиента**: Vite.
- **Хранение БД**: файл в корне проекта (например, `data/app.db`),
  создаётся автоматически при первом запуске, схемы создаются миграцией при старте.
- **Начальные данные**: при первом запуске создаётся расписание по умолчанию
  (рабочие дни Пн–Пт 09:00–18:00, суббота и воскресенье — выходные)
  и владелец «Иван Иванов», email `owner@example.com`.
- Отсутствие авторизации: эндпоинты владельца не защищены, это осознанное упрощение
  демонстрационного приложения.

## 10. Приёмка (критерии готовности)

1. На `/` виден список свободных слотов на 7 дней; прошлых слотов сегодня нет.
2. Запись на слот с валидными данными проходит, появляется страница подтверждения.
3. Занятый слот исчезает из публичного списка; повторная запись на него даёт «Слот занят».
4. Некорректный email или пустое имя отклоняются с сообщением.
5. В настройках можно изменить расписание — публичный список слотов меняется.
6. На `/owner/appointments` видны созданные записи; отмена освобождает слот.
7. Данные переживают перезапуск сервера (хранятся в SQLite).
